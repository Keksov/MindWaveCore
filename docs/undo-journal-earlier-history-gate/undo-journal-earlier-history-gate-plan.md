# undo-journal-earlier-history-gate — план

Показывать пейджер «Ранняя история…» только когда в логе действительно есть история старше
показанного окна журнала.

## 1. Требования владельца (дословно)

1. > «Зачем в журнале отображается надпись "Ранняя история..." Если по ней кликнуть, то она
>    исчезает»

### Уточнение (квиз owner, 2026-07-24)

2. **Решение:** «Скрывать, когда грузить нечего» — кнопка появляется только когда в логе реально
   есть история старше окна.

## 2. Что есть сейчас

Панель — [UndoJournalPanel.vue](../../../GnauralCore/ui/components/UndoJournalPanel.vue), логика
глубокой истории — [use-gtrack-lanes.ts](../../../GnauralCore/ui/composables/use-gtrack-lanes.ts).

Журнал держит в памяти **окно** усвоенных шагов (adopted steps). Всё, что старше окна, живёт только
в серверном логе и подгружается лениво пейджером «Ранняя история…» — страницами по
`DEEP_UNDO_PAGE = 50` (`loadDeepUndoHistory`). Задел под очень длинные истории.

Видимость пейджера:

```ts
const showDeepLoad = computed(() => !gtracks.deepUndoLoaded.value || gtracks.deepUndoHasMore.value)
```

Изначально `deepUndoLoaded = false`, поэтому пейджер показывается **всегда до первого клика** — код
не знает заранее, есть ли что грузить. Клик вызывает `loadDeepUndoHistory`, тот берёт
`from = undoLogPositions[0]` (cid позиции 0 окна). Если старейший коммит окна — корневой снапшот
(`parent === null`), грузить нечего: первая страница `slice(1)` пуста, `deepUndoNextFrom = null`,
`hasMore = false`, `deepUndoLoaded = true` → `showDeepLoad` становится `false` → **кнопка исчезает**.
Ровно то, что видит владелец: пустой клик прячет кнопку.

Обострено фиксом потери журнала (undo-log adopt the FULL main chain): раньше окно обрезалось
`limit: 300` и «ранняя история» иногда реально существовала; теперь окно тянет всю линию от корня,
так что грузить почти всегда нечего — пейджер почти всегда лишний. Живой пример (ForestMeditation):
main-линия = 9 коммитов (корневой снапшот + 8 правок), окно покрывает её целиком; длинные цепочки
573/391/… — заброшенные ветки, не текущая линия.

## 3. Решения

- **EH-D1** — признак «есть ли ранняя история» = **`parent` самого старого коммита усвоенного окна**
  (`undoChain.commits` фетчатся newest-first, старейший — последний). `parent === null` (корень или
  graft-корень после GC) ⟺ старше окна в логе ничего нет ⟺ пейджер не нужен. `undoLogPositions[0]`
  для этого НЕ годится: после adoption он перезаписывается снапшотом позиции 0 (не остаётся `null`),
  так что «cid позиции 0 !== null» — ложный признак.
- **EH-D2** — новый reactive `deepUndoHasEarlier` (ref), выставляется при adoption из fetched-цепочки,
  сбрасывается в `resetUndoLogSync`. `showDeepLoad` умножается на него. Плейн-массив
  `undoLogPositions` не реактивен, поэтому вычислять признак прямо в computed нельзя — нужен ref.
- **EH-D3** — поведение по умолчанию (когда признак ещё не установлен / журнал пуст / не
  синхронизирован) = **скрыто**. Пейджер — не пустой холст, а действие; показываем его только когда
  точно есть что грузить.

## 5. Риски

- **Скрыть кнопку там, где ранняя история ЕСТЬ.** Признак консервативен (`parent !== null` = есть
  предок в логе), так что ложных скрытий быть не должно; но проверить на файле с обрезанным окном
  (если такой воспроизводится) на приёмке.
- **Реактивность признака.** `deepUndoHasEarlier` обновляется только там, где меняется старейший
  коммит окна (reset + adoption). checkout/rollback двигают курсор внутри окна, старейший коммит не
  меняют — признак остаётся верным. Если найдётся путь, обрезающий окно снизу без переустановки
  признака, кнопка может задержаться — вынесено на приёмку.
