## 1. Требования владельца (дословно → нумерованно)

1. Тултипы элементов должны отображаться, **не перекрывая курсор мыши**, **или** отображаться
   **поверх курсора**.
2. **Bug:** в текущей реализации тултип отображается **ниже и под курсором** — это **мешает читать
   текст** на тултипе.
3. **(owner 2026-07-15)** **Все** тултипы в проекте — через **единый общий компонент**; **все
   последующие** тултипы обязаны использовать именно его.
4. **(owner 2026-07-15)** **Исключение из req 3:** «В ECharts пусть остаётся свой механизм, его не
   трогаем» → семейство **D** (5 графиков BodyMonitorCore) выведено из объёма целиком: ни компонент,
   ни правило размещения, ни `position`-колбэк к нему не применяются.

### 1.1. Замечание про «поверх курсора» (req 1, второй вариант)

Системный курсор рисует композитор ОС — он **всегда** поверх содержимого окна. Нарисовать элемент
страницы поверх курсора из браузера **нельзя** (единственный обходной путь — `cursor:none` + свой
курсор, рисуемый на канвасе; ломает нативное поведение, не предлагается).

Но оба варианта req 1 **сходятся в одно решение**: если разместить тултип **выше курсора**, он
одновременно (а) не перекрывается курсором и (б) находится «поверх» (= выше) него. Поэтому
реализуем **один** вариант — **выше** — и он удовлетворяет обе формулировки. Уточнение у владельца
не требуется; вынесено на PAUSE как информация.

## 2. Что уже есть (verified 2026-07-15)

### 2.1. Почему тултип попадает под курсор — геометрия

Hotspot стандартного курсора-стрелки — в его **вершине** (верхний-левый угол), а сам глиф уходит
**вниз-вправо** (~20×20 CSS px при 100%). Следствие:

- всё, что нарисовано **ниже-правее** hotspot'а, — закрывается курсором;
- всё, что **выше** hotspot'а, — **никогда** не закрывается стрелкой (глиф туда не достаёт).

Курсоры с центральным hotspot'ом (`crosshair` на канвасах, `text`, `ns-resize`/`ew-resize`) уходят и
вверх тоже — примерно на 10–16px. Отсюда единая константа зазора **`CURSOR_CLEARANCE_PX = 24`**
(перекрывает и ~20px стрелки, и верхнюю половину крестика).

### 2.3. A — `q-tooltip` (71 шт., все «голые»)

Quasar **2.19.3**, дефолты [QTooltip.js:69-83](../../ui/node_modules/quasar/src/components/tooltip/QTooltip.js#L69-L83):
`anchor: 'bottom middle'`, `self: 'top middle'`, `offset: [14, 14]` → **тултип всегда под элементом**,
т.е. ровно в том квадранте, который занимает глиф стрелки. Ни одного переопределения в коде нет
(`anchor`/`self`/`offset` в проекте встречаются только на `q-menu`/`q-popup-proxy`, не на тултипах).

Плотность: `TracksPanel.vue` — 20, `FsEntryList.vue` — 9, `TrackListView.vue` — 9, `GTrackView.vue` — 7,
`SpectrogramPresetManager.vue` — 5, `SpectrogramView.vue`/`WaveformView.vue` — по 3, остальные 1–2.

- **Глобального конфига тултипов нет.** [quasar.config.ts:94-100](../../ui/quasar.config.ts#L94-L100) —
  единственный Quasar-конфиг в воркспейсе; `framework.config` = `{ dark: true }`. У Quasar v2 **нет**
  механизма дефолтных пропсов компонентов (`framework.config` покрывает только плагины + `ripple`).
- GnauralCore/BodyMonitorCore — плагины без своего `quasar.config`; их подключает
  [module-plugins.ts](../../ui/src/boot/module-plugins.ts) → конфиг MindWaveCore правит все репозитории.

### 2.5. B — кастомные тултипы у курсора (главный подозреваемый по req 2)

- [GTrackView.vue:270-290](../../../GnauralCore/ui/components/GTrackView.vue#L270-L290) `positionTooltip()` —
  тултип узла (GT3.13/GT3.17/GT3.19). Teleport в `<body>`, `position:fixed`, координаты **viewport**
  (`clientX/clientY`, [:838](../../../GnauralCore/ui/components/GTrackView.vue#L838)):
  `left = anchor.x + 14`, `top = anchor.y + 14`, затем `nextTick` с замером и **флипом только при
  переполнении** правого/нижнего края + клампом (`pad = 8`).
- [SpectrogramView.vue:813](../../../GnauralCore/ui/components/SpectrogramView.vue#L813) — readout у курсора
  (SF-D25): `tooltipPos = { x: aEvent.offsetX + 12, y: aEvent.offsetY + 12 }`, координаты
  **контейнера** (`offsetX/offsetY`), `position:absolute`, **без клампа и флипа вообще** (может
  вылезти за правый/нижний край контейнера).

Оба кладут тултип **вниз-вправо на 12–14px** от hotspot'а — т.е. **прямо под глиф стрелки** (~20px):
курсор накрывает левый-верхний угол тултипа, где начинается первая строка текста. Это точно
соответствует req 2. Показательно, что в
[SpectrogramView.vue:812](../../../GnauralCore/ui/components/SpectrogramView.vue#L812) комментарий гласит
«*offset a little so it doesn't sit under the pointer*» — **намерение было верным, направление
сдвига — нет**.

Расхождения между двумя реализациями: система координат (`clientX/Y`+`fixed` vs `offsetX/Y`+`absolute`),
сдвиг (+14 vs +12), `z-index` (7000 vs 7), обработка краёв (флип+кламп vs ничего). Req 3 эти
расхождения снимает по построению — обе поедут на общий компонент.

## 3. Решения

- **TT-D1 — Единое правило: тултип размещается ВЫШЕ курсора/элемента (req 1).** Базовое направление —
  **вверх**; запасное (когда сверху не помещается) — вниз, но с зазором **не менее
  `CURSOR_CLEARANCE_PX = 24`** от hotspot'а, чтобы глиф стрелки не накрыл текст. Константа — в одном
  месте (TT-D3), т.к. размер курсора из браузера не читается (R3). «Выше» удовлетворяет обе
  формулировки req 1 (§1.1).
- **TT-D2 — ~~Глобальный дефолт `q-tooltip` через boot-файл (мутация `QTooltip.props`)~~ ОТМЕНЁНО
  (owner 2026-07-15, req 3).** Владелец выбрал **единый общий компонент** — он и есть точка, где
  задаются `anchor`/`self`/`offset`. Boot-хак больше не нужен; вместе с ним **снят риск R2** (опора на
  приватную форму `QTooltip.props` и её поломка при апгрейде Quasar). Компонент строго лучше: правило
  видно в коде, а не спрятано в boot.
- **TT-D7 — Где живёт компонент: MindWaveCore + алиас `@tooltip`, по образцу PW-D8 (req 3).** Новый
  `MindWaveCore/ui/src/components/tooltip/` (`AppTooltip.vue` + `tooltip-place.ts`), Vite-алиас
  `'@tooltip'` в [quasar.config.ts:27-31](../../ui/quasar.config.ts#L27-L31) рядом с `@panel` и
  `paths` `"@tooltip/*": ["./src/components/tooltip/*"]` в [tsconfig.json](../../ui/tsconfig.json).
  Импорт из любого репозитория: `import AppTooltip from '@tooltip/AppTooltip.vue'` — ровно как
  `@panel/PanelWindow.vue` сегодня (§2.4). Своих `paths` module-репозиториям не нужно: `vue-tsc`
  идёт из `MindWaveCore/ui` по графу импортов. *Имя (`AppTooltip` / тег `<app-tooltip>`) — на
  утверждение владельцем на TT1.3.*
- **TT-D8 — API компонента: два режима, чтобы под req 3 попали и канвас-тултипы.** Один компонент,
  одна визуальная подача, одно правило размещения (TT-D1), два способа привязки:
  - **режим элемента** (по умолчанию) — внутри рендерит `<q-tooltip anchor="top middle"
    self="bottom middle">`; покрывает семейства **A** (71) и **C** (~17). `offset` остаётся `[14,14]`:
    при `anchor:'top'` нижний край тултипа встаёт на 14px выше верхней границы элемента, курсор при
    этом **внутри** элемента, а стрелка уходит вниз-вправо → перекрытия нет;
  - **режим курсора** — проп вида `:at="{ x, y }"` (viewport-координаты): Teleport в `<body>` +
    `position:fixed`, позиция считается `placeCursorTooltip` (TT-D3); покрывает семейство **B** (2).
  Зачем один компонент на оба: иначе канвас-тултипы остаются вне req 3 и снова разъедутся по стилю и
  правилу (сегодня они разъехались именно так — §2.5).
- **TT-D3 — Чистый модуль размещения `tooltip-place.ts` + bun-тесты — единственный источник правила.**
  `placeCursorTooltip({ x, y, w, h, bounds, clearance })` → `{ left, top }`: базово **выше** курсора
  (`top = y - h - clearance`), при нехватке места сверху — **ниже** с тем же зазором
  (`top = y + clearance`), горизонталь `left = x + 14` с флипом влево у правого края и финальным
  клампом в `bounds` (`pad = 8`). Чистый TS, без Vue → тестируется `bun test`. Лежит рядом с
  компонентом (`@tooltip/tooltip-place.ts`), прецедент — [time-format.ts](../../../GnauralCore/ui/composables/time-format.ts) (SB-D4).
- **TT-D4 — Семейство B переезжает на компонент (режим курсора).** `GTrackView.positionTooltip()`
  (вся арифметика `+14/+14` + флип + кламп) и `SpectrogramView` (`+12/+12`, без клампа) удаляются;
  оба рендерят `<app-tooltip :at="hoverPos">`. `SpectrogramView` при этом **получает кламп, которого
  у него нет**, и переводится на viewport-координаты (`clientX/Y`) — это требование режима курсора, а
  не отдельная опция (R4).
- **TT-D5 — Семейство C: нативные `title=""` → компонент (req 3; больше НЕ опционально).** Раньше было
  «proposed, снимается целиком»; req 3 делает конвертацию **обязательной** — позиция нативного тултипа
  из кода не управляется, значит удовлетворить req 1 и req 3 можно только конвертацией. Побочный
  эффект: меняется стиль и задержка (ОС ~500ms → Quasar 0ms) — **видимое изменение**, показать
  владельцу на TT1.3. `aria-label` сохраняем; `title`-как-проп (§2.6) не трогаем.
- **TT-D6 — Семейство D (ECharts): ВНЕ ОБЪЁМА (req 4; LOCKED owner 2026-07-15).** Владелец: «в ECharts
  пусть остаётся свой механизм, его не трогаем». Отклонены оба ранее предложенных варианта — и (а)
  `tooltip.show:false` + `<app-tooltip>` (рисковал потерять `trigger:'axis'`/`axisPointer`/форматтеры),
  и (б) общий `position`-колбэк на `tooltip-place.ts`. **5 графиков BodyMonitorCore не трогаем вообще.**
  Следствия, которые надо помнить: (1) req 3 получает **документированное исключение** — «все тултипы
  через компонент» = семейства A/B/C; (2) тултипы ECharts по-прежнему могут попадать под курсор (req 1
  к ним не применяется); (3) фаза 3 снята, риск R7 закрыт; (4) guard TT-D9 обязан ECharts **не** ловить.
- **TT-D9 — Enforcement: guard-тест вместо lint-правила (req 3, «все последующие»).** ESLint в проекте
  нет (§2.8), поэтому «обязаны использовать компонент» подпирается bun-тестом, который сканирует
  исходники трёх репозиториев и падает при: сыром `<q-tooltip` вне `AppTooltip.vue`; `title="`/`:title="`
  на DOM-элементах; ручных тултип-дивах. **Allowlist обязателен** (иначе ложные срабатывания):
  `AppTooltip.vue` (единственный легальный `q-tooltip`), `title`-как-проп `PanelWindow`
  (`TrackListDialog.vue:10`, `FileOpenDialog.vue:8`), **5 ECharts-графиков BodyMonitorCore** (req 4 —
  вне объёма). Без этого шага req 3 остаётся документацией, а не правилом.

## 5. Риски

- **R1 — Quasar сам возвращает тултип вниз (verified).**
  [`applyBoundaries`, position-engine.js:303-343](../../ui/node_modules/quasar/src/utils/private.position-engine/position-engine.js#L303-L343):
  если при `anchor:'top'`/`self:'bottom'` тултип не влезает сверху (`props.top < 0`) и якорь в верхней
  половине экрана, срабатывает ветка `props.top = Math.max(0, anchorProps.bottom)` — т.е. **флип
  обратно вниз, под курсор**. Касается элементов у самой верхней кромки окна — в первую очередь двух
  тултипов шапки [MainLayout.vue:6,9](../../ui/layouts/MainLayout.vue#L6-L9). Тулбар «Треков» лежит
  ниже шапки приложения, места над кнопками хватает. **Митигация:** поведение в этих случаях не хуже
  текущего; общий компонент даёт **одну точку** для лечения (например, авто-переход в режим курсора у
  кромки). Проверить на TT1.3.
- **R2 — ЗАКРЫТ (owner 2026-07-15):** boot-хак с мутацией `QTooltip.props` отменён в пользу общего
  компонента (TT-D2) — опоры на приватное API Quasar больше нет.
- **R3 — Размер курсора из браузера не читается.** Windows позволяет увеличивать курсор (до ~4–15×);
  при крупном курсоре зазор в 24px недостаточен для **запасного** («вниз») размещения. Основное
  («вверх») от размера курсора не зависит — стрелка растёт вниз-вправо. **Митигация:** одна константа
  `CURSOR_CLEARANCE_PX` в общем модуле; при жалобе — поднять в одном месте.
- **R4 — TT2.4: смена системы координат.** `offsetX/offsetY` считаются от **target'а события** (может
  быть канвас/оверлей, а не контейнер) — перевод на `clientX/Y` способен сдвинуть тултип.
  **Митигация:** отдельный шаг, ручная проверка на TT2.6.
- **R5 — Объём миграции: ~90 точек вызова в 3 репозиториях за раз.** Механическая, но широкая правка;
  риск пропустить/сломать отдельные тултипы. **Митигация:** PAUSE TT1.3 **до** миграции (API
  утверждён на 2–3 местах); шаги разбиты по семействам (A / C / B) и коммитятся по репозиториям;
  guard TT2.5 ловит пропущенные.
- **R6 — «Поверх курсора» буквально невыполнимо** (ОС рисует курсор поверх окна). Реализуем «выше»,
  что удовлетворяет обе формулировки req 1 (§1.1).
- **R7 — ЗАКРЫТ (owner 2026-07-15, req 4):** семейство D выведено из объёма целиком — ECharts не
  трогаем, значит и риска потерять `axisPointer`/форматтеры нет.
- **R8 — Guard без ESLint даёт ложные срабатывания.** Наивный греп по `title=` поймает `title`-как-проп
  `PanelWindow` (§2.6) и тексты/атрибуты, не относящиеся к тултипам. **Митигация:** явный allowlist в
  TT-D9 + тест обязан быть зелёным на текущем дереве до того, как краснеет на подсадке.
