# point-mode-removal — план

Убрать выделенный «Режим правки точек» (кнопка `edit_location_alt` в шапке gtrack-дорожки, GT3.1 →
GT10.5 «режим глобальный»), перенеся его единственное оставшееся отличие — мульти-выбор точек по
Ctrl/Shift — в обычный режим отображения графика.

## Требования владельца (verbatim)

1. «Избавиться от выделенного "Режима правки точек". Сейчас единственное отличие этого режима от
   стандартного стостоит в том, что он позволяет выделить несколько точек с Ctrl или Shift, эту
   возможность нужно реализовать в обычном режиме отображения графика.» (2026-07-23)

## Что режим делал на самом деле (инвентаризация перед правкой)

`pointMode` (проп `GTrackView`) гейтит ровно шесть вещей:

| # | Место | В режиме | В обычном |
|---|---|---|---|
| 1 | [GTrackView.vue:9-11](../../../GnauralCore/ui/components/GTrackView.vue) курсоры | pointer над вершиной, ns-resize над кромкой полосы | курсор всегда `pointer` (проп `seekable=true`) |
| 2 | [GTrackView.vue:314](../../../GnauralCore/ui/components/GTrackView.vue) `autoAxis` | запас по оси Y | запас только во время drag (GT10.39-followup) |
| 3 | [GTrackView.vue:587](../../../GnauralCore/ui/components/GTrackView.vue) `baseR` | точки 3.5 px | точки 2 px |
| 4 | `onPointerDown` | простой drag двигает вершину; клик по пустому месту снимает выделение | вершину двигает **Ctrl**+drag (GT10.10, треб. 57-58); клик по пустому месту двигает плейхед |
| 5 | `onPointerDown` | **Ctrl/Shift+клик по вершине → мульти-выбор** (GT3.15, треб. 30) | мульти-выбора нет |
| 6 | `onClick` | клики инертны (всё на pointerdown/up) | клик по вершине открывает инспектор, по пустому — seek |

Т.е. отличий формально больше одного, но содержательно значимо только **#5**: остальное — либо
косметика (#1-#3), либо поведение обычного режима, которое владелец и хочет оставить (#4, #6).
Поэтому «стандартное» поведение сохраняется 1:1, а мульти-выбор добавляется как новый жест.

## Решения

- **PM-D1.** Жест мульти-выбора в обычном режиме: **Ctrl/Shift + клик по вершине** (нажатие-отпускание
  без движения) переключает точку в мульти-выборке. **Ctrl+drag по-прежнему двигает вершину**
  (GT10.10 не ломается): «клик» от «драга» отличает уже существующий порог `DRAG_THRESHOLD_PX`.
  Ничего не теряется: Ctrl+клик без движения раньше открывал инспектор — ровно то же, что делает
  обычный клик, т.е. был дубликатом. Обычный (без модификатора) клик по вершине по-прежнему
  открывает инспектор.
- **PM-D2.** `select-point` на модификаторном нажатии **откладывается до первого реального движения**.
  Причина: хост ([TracksPanel.vue:295](../../../GnauralCore/ui/components/TracksPanel.vue))
  на `@select-point` вызывает `clearMultiSelection()` — если эмитить его на pointerdown (как делает
  обычный `beginVertexDrag`), каждый Ctrl+клик стирал бы накопленную выборку. В режиме этой проблемы
  не было, потому что там ветка мульти-выбора возвращалась ДО начала драга.
- **PM-D3.** Shift остаётся только жестом мульти-выбора: добавление узла по клику на кривую и drag
  кромок (beat-полоса / коридор баланса) остаются на Ctrl, как сейчас. Shift+drag по вершине её
  двигает — побочный эффект общего пути, вреда нет (Shift+drag на канве раньше не значил ничего;
  Shift на **колесе** — панорама времени — не затрагивается).
- **PM-D4.** Визуал = обычный режим: `baseR` 2 px, запас по оси только во время drag. Курсоры
  `--point`/`--value-edge` становятся безусловными: hover-хит-тест и подсказка и так работают вне
  режима (GT3.17), так что курсор просто перестаёт им противоречить.
- **PM-D5.** Сброс мульти-выборки: Escape (закрывает инспектор и чистит выборку, GT3.16) или обычный
  клик по вершине (`select-point` → `clearMultiSelection`). Клик по пустому месту, как и раньше в
  обычном режиме, двигает плейхед и выборку не трогает.
- **PM-D6.** `navigateToDiagnostic` ([TracksPanel.vue:1216](../../../GnauralCore/ui/components/TracksPanel.vue))
  больше не включает режим — только выделяет точку.

## Шаги

- **Фаза 0** — PM0.1: план + progress.json.
- **Фаза 1** — PM1.1: `GTrackView` — жест мульти-выбора в обычной ветке `onPointerDown` (PM-D1/D2),
  отложенный `select-point`, Shift-гард в `onClick`. Режим ещё на месте (коммит компилируется сам по себе).
- **Фаза 2** — PM2.1: удаление режима: проп `pointMode` и все его ветки (`GTrackView`), кнопка +
  проп + `navigateToDiagnostic` (`TracksPanel`), `pointModeLanes`/`isLanePointMode`/
  `toggleLanePointMode` (`use-gtrack-lanes`), ключ `audio.gtrackPointMode` (ru/en).
- **Фаза 3** — PM3.1: PAUSE — приёмка владельцем в реальном приложении.

## Риски

- **Стирание мульти-выборки** — главный риск (PM-D2): любой путь, эмитящий `select-point` на
  модификаторном нажатии, ломает накопление. Проверять на 3+ точках.
- **Двойная обработка**: после pointerup браузер шлёт `click` — `onClick` обязан игнорировать
  модификаторные клики по вершине, иначе Shift+клик и выберет точку, и откроет инспектор.
- **Потеря Ctrl+drag** (GT10.10, треб. 57-58) — регресс, если жест повесить на pointerdown вместо
  pointerup.
- Кнопка режима была ещё и якорем фокуса для Ctrl+Z (комментарий в `TracksPanel` про «the point-mode
  toggle») — сам обработчик клавиш от неё не зависит, но комментарий надо поправить, чтобы не
  ссылаться на удалённый контрол.
- Ключ `gtrackPointMode` удалять в обоих локалях сразу (ru + en).

`GnauralCore`: `bun test ui server`. `MindWaveCore/ui`: `bun run typecheck` + `bun run build`.
Ручной сценарий (владелец, PM3.1): обычный клик по вершине → инспектор; Ctrl+drag → вершина

клик по пустому месту → плейхед; кнопки режима в шапке дорожки нет.
