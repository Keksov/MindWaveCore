# volume-balance-band — совместный график «Громкость + Баланс» (коридор баланса)

Дата: 2026-07-17. Леджер: `volume-balance-band-progress.json` (авторитетный статус — там).

Аналог уже сделанной фичи **«Базовая частота + Полоса бита»** (owner 2026-07-14, `beatBand`): вокруг
линии *Базовая частота* рисуется коридор `база ± бит/2`, края которого можно тянуть. Здесь то же самое
для пары *Громкость / Баланс*: вокруг линии **Громкость** рисуется коридор **Баланс**, а его вершины
(края) редактируются.

## 1. Требования владельца (дословно)

> Новый план + леджер. Совместный режим отображения графика Горомкост + Баланс на одном графике.
> 1. Реализовать режим отображения графика громкости по аналогии с "Базовая частота" + "Полоса бита" -
>    Вокруг линии громкости отображается "коридор" графика "баланс".
> 2. Вершины графика Баланс можно редактировать

## 2. Инвентаризация (что есть в коде сейчас)

Всё в `GnauralCore/ui` (**CRLF!**, см. R1). Режимы графика: `base | beat | volume | balance`
(`gtrack-render.ts:7-8`).

### 2.1. Модель точки (raw-поля и производные оси) — `composables/gtrack-model.ts`

- Хранимые поля точки: `baseFreq, beatFreqHalf, volL, volR` (`gtrack-model.ts:20-26`). Производные оси
  (GT-D6) считаются при отрисовке, не хранятся.
- `pointVolume(p) = (volL + volR) / 2` (`:189-191`) — средняя громкость (это и есть линия «Громкость»).
- `pointBalance(p) = (volR − volL) / (volL+volR)`, `[−1, 1]`; `sum==0 → 0` (`:192-197`).
- Обратное преобразование для баланса уже есть: `valuePatchForMode(p,'balance',b,mono)` при фиксированной
  **сумме** `s=volL+volR` даёт `volL = s(1−b)/2`, `volR = s(1+b)/2` (`gtrack-render.ts:55-61`). То есть при
  фиксированной громкости `V=s/2`: `volL = V(1−b)`, `volR = V(1+b)`.

**Ключевое геометрическое наблюдение.** `V − volL = volR − V = (volR−volL)/2 = V·b`. Значит `volL` и
`volR` **симметричны** относительно `V`, ровно как `база ± бит/2` симметричны относительно базы. И `volL,
volR ∈ [0,1]` — те же единицы, что и ось «Громкость» (linear 0..1), поэтому коридор рисуется прямо на
этой оси **без расширения** (в отличие от beat, где `bit/2` мог выйти за диапазон базовых частот и ось
приходилось расширять — `gtrack-render.ts:254-261`).

## 3. Решения (VB-Dn)

> VB-D3 (семантика перетаскивания края) — **РЕШЁН на VB0.1 владельцем: вариант A (симметрично, громкость
> фиксирована)**. Остальные — прямое зеркало
> beatBand, вынесены как решения для протокола, менять их вряд ли нужно.

- **VB-D1 (форма режима) = пер-дорожечный тумблер `balanceBand` на дорожке `volume`**, а НЕ пятый
  `GTrackMode`. В режиме «Громкость» с включённым тумблером вокруг средней линии рисуется коридор
  `[volL, volR]`. Точное зеркало `beatBand` на дорожке `base`. Обоснование: владелец прямо задал аналогию
  с base+bit; значения баланса живут в тех же единицах, что и ось громкости (0..1), новая ось не нужна.
- **VB-D2 (геометрия коридора).** Линия = `V=(volL+volR)/2` на оси 0..1. Края коридора = `volL` и `volR`
  (оба в 0..1), симметричны относительно `V` с полушириной `h=|volR−volL|/2 = V·|balance|`. Заливка между
  краями + тонкая центральная линия на `V`. При `balance==0` коридор схлопывается в линию (ручек нет —
  как при `beatFreqHalf<=0`). Расширение оси НЕ требуется (`volL,volR ≤ 1 =` максимум оси всегда).
- **VB-D3 (редактирование края) — РЕШЕНО на VB0.1: вариант A, симметрично (громкость фиксирована).**
  Требование 2 «вершины графика Баланс
  редактируются». Варианты:
  - **(A, рекомендую) Симметрично, громкость фиксирована** — зеркало beat. Тянем край → меняется
    `|balance|` (ширина коридора) при фиксированных `V` и знаке (какой канал громче); противоположный
    край едет симметрично. `b_new = sign(b_old)·|курсор−V|/V`, клампится `|b|≤1`; реиспользуем
    `valuePatchForMode(p,'balance',b_new,mono)`. Центр (`b=0`) не имеет схватываемых краёв — баланс с
    нуля создаётся отдельным графиком «Баланс» или диалогом точки (ровно как нельзя схватить полосу бита
    при `бит=0`). Плюс вершину громкости по-прежнему можно тянуть (режим volume уже это умеет) — весь
    коридор едет вместе с ней, ширина масштабируется пропорционально (ratio=balance сохраняется).
  - **(B) Свободный край = задаёт канал.** Тянем верхний/нижний край → напрямую ставим `volR`/`volL`;
    меняются и баланс, и громкость; можно перейти центр. Мощнее, но не зеркалит beat и линия громкости
    «прыгает» под курсором во время правки баланса.
  - Примечание: возможен и (C) — знаковый край при фиксированной `V` (курсор ниже `V` → баланс уходит в
    минус, края визуально перекрещиваются). Упоминаю для полноты; по умолчанию не предлагаю.
- **VB-D4 (моно / вырожденные случаи).** У моно-голоса нет стерео-баланса → тумблер скрыт/недоступен и
  коридор не рисуется (зеркало: полоса бита только в `base`; `valuePatchForMode('balance')` при `mono`
  возвращает `{}`). Точка с `volL==volR` (центр) — ручек нет (края совпали с линией). Тишина
  (`volL=volR=0`) — баланс не определён, коридора нет.
- **VB-D5 (hover / захват / undo / отрисовка).** Переиспользуем механику hoverEdge + drag-транзакции:
  добавляем состояние `BalanceEdgeRef`/`hoverEdge`-аналог (или обобщаем `BeatEdgeRef`). Один drag = одна
  единица undo (`beginPointDrag → commit`); press-release без движения открывает диалог точки (поле
  «Баланс»). Стиль: одна полупрозрачная заливка (α ≈ 0.18) + маленькие ручки на краях + центральная линия;
  цвет — от цвета голоса, как у beat.
