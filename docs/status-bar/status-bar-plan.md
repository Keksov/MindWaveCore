# status-bar — статус-бар внизу редактора треков (позиция курсора + форматы + минимап)

**Owner request (2026-07-14):** во вкладке «Треки» сделать **статус-бар внизу области треков**,
всегда видимый (не участвует в скролле дорожек). В нём — редактируемая позиция курсора с выбором
формата отображения (per file), длительность (read-only) и минимап, чьё начало совпадает с
вертикальной осью графиков.

Ledger (authoritative): [status-bar-progress.json](status-bar-progress.json).
Методология Plan+Ledger — как в [gtrack-editor](../gtrack-editor/gtrack-editor-plan.md):
atomic per-step commits (префикс id шага), `verify` перед `done`, пауза на owner-чекпоинтах.
Работаем **только во вкладке «Треки»** (`TracksPanel.vue`); старые вкладки заморожены (R7 GT-D10).

## 1. Требования владельца (дословно → нумерованно)

1. **Статус-бар находится внизу области треков и всегда виден** (не участвует в скролле треков).
2. В нижней части тулбара отображаются следующие поля:
   - **(а)** текущая **позиция курсора** с возможностью **редактирования значения**;
   - **(б)** позиция может отображаться в **нескольких форматах**. Справа в этом блоке есть
     **шестерёнка** со списком форматов (формат подбирается **автоматически** в зависимости от
     длительности записи; **должен сохраняться для конкретного файла**):
     - сек.
     - сек. + миллисек.
     - чч:мм:сс
     - дд:чч:мм:сс
     - чч:мм:сс + сотые
     - чч:мм:сс + миллисек.
     - ~~чч:мм:сс + сэмплы~~ **(owner 2026-07-14: не используем — исключён из набора)**
   - **(в)** **длительность** (только для чтения).
3. **Минимап** должен находиться **в статус-баре сверху**; **начало минимапа должно визуально
   совпадать с вертикальной осью на графиках**, т.е. справа от него должно быть свободное место.
4. **(owner 2026-07-14)** Уменьшить **зазор слева и справа** от треков до границы области редактора
   **до 2px**.

## 2. Что уже есть (verified 2026-07-14)

- **Хост:** [TracksPanel.vue](../../../GnauralCore/ui/components/TracksPanel.vue) — корень
  `.audio-page__output-section--spectrogram` c `overflow:auto` (**весь стек скроллится**). Внутри:
  тулбар (slot), **липкая шапка** `.audio-page__spectrogram-header` (`position:sticky; top:-16px;
  z-index:40`), gtrack-стек, общие волна/спектр и — в самом низу, **внутри области скролла** —
  `.audio-page__minimap-wrap` c `<spectrogram-minimap>` + шестерёнка режима минимапа (SF26). Значит
  минимап сейчас **уезжает** при скролле дорожек вниз.
- **Плейхед/курсор:** `localPlayheadSec` (персистентный локальный курсор, GT10.32) →
  `gtrackPlayheadSec`; сдвигается через `handleSeek(aSec)`. При остановленном транспорте курсор
  сохраняется. Это единственный источник «текущей позиции».
- **Длительность:** computed `spectrogramDuration` = `backendAnalysis.durationSec ||
  gtracks.durationSec.value`.
- **Ось графиков:** во всех view (GTrackView/WaveformView/SpectrogramView) поле графика —
  `AXIS_MARGIN = { left: 46, right: 8 }` (GTrackView.vue:280): область данных начинается на **46px**
  от левого края и заканчивается **8px** от правого. Минимап нужно выровнять по этим же вставкам.
- **Per-file персист:** паттерн в [use-gtrack-lanes.ts](../../../GnauralCore/ui/composables/use-gtrack-lanes.ts)
  — `localStorage` ключ `mindwave-*` хранит map `{[filePath]: value}`, ключ = `filePath.value`.
  Так же персистятся высоты/раскладка/спектр-оверрайды. Формат позиции сохраняем этим же способом.
- **Горизонтальный зазор:** корень `.audio-page__output-section` имеет `padding:16px` со всех сторон
  (липкая шапка компенсирует верх через `top:-16px`). Req 4 — уменьшить **левый/правый** padding до
  2px; верх/низ не трогаем (компенсация шапки остаётся прежней).
- ~~**Sample rate** (для формата «чч:мм:сс + сэмплы») берём из бэкенд-анализа (`SpectrogramAnalysisInfo`;
  там уже есть `durationSec`/`channelCount` после GT7.1). **Формат «сэмплы» исключён (owner
  2026-07-14) — sampleRate больше не нужен.**~~

## 3. Решения (SB-D5/D7 locked owner 2026-07-14; остальные proposed — owner-review на SB2.5)

- **SB-D1 — реструктуризация раскладки: скролл-область + фиксированный низ.** Сейчас скроллится
  весь корень. Делаем корень flex-колонкой из трёх зон: (1) тулбар (`flex:0 0 auto`, уже сверху),
  (2) **скролл-область дорожек** (`flex:1 1 auto; overflow:auto`) — сюда переезжает всё, что сейчас
  скроллится (шапка остаётся `sticky` внутри неё, gtrack-стек, общие волна/спектр), (3) **статус-бар**
  (`flex:0 0 auto`) — новый компонент внизу, **вне** скролла, всегда виден (req 1). Липкая шапка и
  выплывающие панели (GT10.27 `--tp-*`) продолжают работать — их измерение опирается на видимую рамку
  контейнера; проверить, что смена скролл-контейнера не ломает `measureOverlayFrame`.
- **SB-D2 — минимап переезжает в статус-бар (верхняя строка) (req 3).** `.audio-page__minimap-wrap`
  (минимап + шестерёнка режима SF26) вынимается из низа скролла и становится **верхней строкой
  статус-бара**. Выравнивание: обёртка минимапа получает `padding-left:46px; padding-right:8px`
  (= `AXIS_MARGIN`), чтобы **t=0 минимапа совпал с левым краем области данных графиков**, а справа
  осталось свободное место (req 3). Шестерёнка режима садится в свободное правое поле. Поведение
  минимапа (view/zoom/pan) не меняется.
- **SB-D3 — статус-бар как отдельный компонент.** Новый `TrackStatusBar.vue` (в `GnauralCore/ui/
  components/`): props `positionSec`, `durationSec`, `sampleRate`, `format`, слот/область под минимап
  сверху; emits `update:positionSec` (seek) и `update:format`. Держит верстку в одном месте, тестируем
  и переиспользуем. Хост (`TracksPanel`) прокидывает `gtrackPlayheadSec`/`spectrogramDuration`, а
  `update:positionSec` → `handleSeek`.
- **SB-D4 — чистый модуль форматирования времени `time-format.ts` + тесты.** 7 форматов (req 2б) как
  enum/константа; `formatTime(sec, fmt, sampleRate)` и `parseTime(str, fmt, sampleRate)` (обратный
  разбор для редактирования, req 2а) + `autoPickFormat(durationSec)`. Разбор толерантен к неполному
  вводу в рамках формата; результат клампится в `[0, durationSec]`. Bun-тесты round-trip
  format→parse для каждого формата.
- **SB-D5 — авто-подбор формата + персист per file (req 2б; LOCKED owner 2026-07-14).**
  **Набор — 6 форматов** (owner исключил «чч:мм:сс + сэмплы»). `autoPickFormat` по длительности
  (пороги **подтверждены** владельцем):
  - `< 60 с` → **сек. + миллисек.**;
  - `< 1 ч` → **чч:мм:сс + сотые**;
  - `< 24 ч` → **чч:мм:сс**;
  - `≥ 24 ч` → **дд:чч:мм:сс**.
  Явный выбор пользователя перекрывает авто-подбор и **сохраняется per file** (`localStorage`
  `mindwave-tracks-timeformat` = `{[filePath]: formatId}`, паттерн use-gtrack-lanes). Нет сохранённого
  → авто-подбор. `sampleRate` больше не требуется (формат «сэмплы» снят) — риск R2 закрыт.
- **SB-D6 — позиция редактируемая, длительность — read-only, оба в текущем формате (req 2а/2в).**
  Поле позиции — редактируемое (`q-input`/inline): commit по Enter/blur → `parseTime` → clamp →
  `handleSeek`; во время проигрывания поле показывает живую позицию (когда не в фокусе редактирования).
  Длительность — тот же формат, **read-only**.
- **SB-D7 — горизонтальный зазор 2px (req 4; LOCKED owner 2026-07-14).** Левый/правый `padding`
  корня `.audio-page__output-section` уменьшить с 16px до **2px** (`padding:16px 2px`); верх/низ =
  16px без изменений (компенсация липкой шапки `top:-16px` остаётся). Не затрагивает выравнивание
  минимапа (оно опирается на `AXIS_MARGIN` внутри канваса, а не на padding секции).

## 5. Риски

- **R1 — реструктуризация скролла (SB-D1).** Перенос `overflow:auto` с корня на внутренний контейнер
  может сломать: (а) `sticky` шапку (пересчитать `top`, сейчас `-16px` компенсирует padding корня);
  (б) `measureOverlayFrame`/`--tp-*` (GT10.27) — рамка выплывающих панелей меряется от контейнера;
  (в) `scrollIntoView` для «+ дорожка» (GT10.28). Проверить все три вручную на PAUSE.
- **R2 — ЗАКРЫТ (owner 2026-07-14):** формат «чч:мм:сс + сэмплы» снят, `sampleRate` не нужен.
- **R3 — точность позиции при loops.** `durationSec` рендера при `loops>1` (ср. R3 gtrack-editor) —
  позиция/длительность считаются по той же оси, что и графики; сверить, что клампы согласованы.
- **R4 — редактируемое поле vs живой плейхед.** Во время проигрывания поле не должно перетирать ввод
  пользователя: обновлять отображаемое значение только когда поле не в фокусе редактирования (SB-D6).
