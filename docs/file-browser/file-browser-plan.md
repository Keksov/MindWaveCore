# file-browser — универсальный диалог открытия файлов с адаптерами источников

**Owner request (2026-07-12):** полностью переписать диалог выбора файлов в редакторе. Сейчас он
ограничен единственной папкой (`presetsRoot`); нужно, чтобы он мог открывать **любой файл на
компьютере**. Обсуждение вариантов (FPC-CLI vs Bun/TS vs гибрид) завершено — принято решение
делать **всё на TS/Bun за абстракцией провайдеров-адаптеров**; FPC-CLI отклонён (Bun уже является
файловым data-plane и самодостаточным агентом-на-хост, FPC-CLI в репозитории — это DSP-движок и
webview-хост, а не файловый сервис).

Ledger (authoritative): [file-browser-progress.json](file-browser-progress.json).
Методология Plan+Ledger — как в [gtrack-editor](../gtrack-editor/gtrack-editor-plan.md) и
[spectrogram-fixes](../spectrogram-fixes/spectrogram-fixes-plan.md): atomic per-step commits
(префикс id шага, напр. `FB1.2 ...`), `verify` перед `done`, пауза на owner-чекпоинтах.

## 1. Требования владельца (дословно → нумерованно)

1. Диалог должен уметь дойти до **любого файла на компьютере** (навигация по всей ФС), а не быть
   заперт в одной папке. При этом в списке показываются **только поддерживаемые редактором типы**
   (аудио/gnaural) — фильтр типов по умолчанию; каталоги для навигации видны всегда (owner
   2026-07-12).
2. **Безопасность:** этот функционал доступен **только для локального хоста** (loopback);
   удалённые клиенты не получают доступ к обзору/открытию произвольных файлов. **Механизм
   (owner 2026-07-12): отдельный bind на `127.0.0.1`** — file-browse эндпоинты слушают отдельный
   loopback-only сокет.
3. UI должен быть **универсальным (кросс-платформенным)**: заранее учесть, что **диски (буквы)
   есть только в Windows**; на других ОС корни файловой системы устроены иначе. Разница по ОС не
   должна протекать в UI.
4. Архитектура — **адаптеры (провайдеры источников)**: локальная ФС сейчас; в будущем — удалённые
   хосты, чтение файлов из **БД** и **из веба** как отдельные провайдеры за тем же UI.
5. **Три режима отображения** списка файлов:
   - **линейный список** — только имена, плотно;
   - **иконки** разного размера (мелкие / средние / крупные);
   - **табличный вид** «как в Total Commander» (колонки имя / расширение / размер / дата /
     атрибуты, сортировка по каждой колонке в обе стороны).
6. Сразу нужен **встроенный regexp-фильтр** списка файлов — инкрементальный быстрый фильтр «как
   Ctrl-S в Total Commander» (набор символов сужает список на лету, Esc сбрасывает).
7. Производительность работы с ФС и **сортировка по разным атрибутам** — учесть заранее.
8. Весь UI — на текущем **Quasar**-стеке.
9. (owner 2026-07-12) Добавить **menu bar как в классическом приложении**. Пункт **Файл → Открыть**
   вызывает новый диалог.
10. (owner 2026-07-12) Старый `q-tree`-браузер пресетов **оставляем на месте на время миграции** —
    новый диалог добавляется рядом, а не заменяет его сразу.
11. (owner 2026-07-12) В диалоге должна быть возможность **добавлять источники в список
    фаворитов** — папки, файлы и т.п.; фавориты сохраняются и доступны для быстрого перехода.

## 2. Контекст текущей реализации (что переписываем)

- Обзор файлов сейчас — серверный обход одного каталога `presetsRoot` через `node:fs/promises`,
  отдаётся в UI как дерево `q-tree`. См.
  [audio-file-utils.ts](../../../GnauralCore/server/audio-file-utils.ts) и
  [AudioPage.vue](../../../GnauralCore/ui/pages/AudioPage.vue).
- «Ограничение одной папкой» — это **намеренная песочница**: `isPathInsideBase`
  ([audio-file-utils.ts:62-90](../../../GnauralCore/server/audio-file-utils.ts#L62-L90)) режет
  доступ до единственного корня. «Открыть любой файл» = снять/расширить это ограничение и добавить
  обход произвольных каталогов, при этом **сохранив** канонизацию путей и заменив песочницу
  на **loopback-гейт** (req 2).
- Bun/TS уже является файловым data-plane (readdir/stat/realpath) и общается с UI по WebSocket —
  новый диалог встраивается в ту же связку без новых технологий.

## 3. Архитектура (принятые решения — детали в ledger `decisions`)

- **`FileSourceProvider`** — интерфейс адаптера: `id`, `listRoots()`, `listDir(path, opts)`,
  `stat(path)`, `openStream(path)`. Реестр провайдеров на сервере; UI выбирает провайдера по `id`.
- **`LocalFsProvider`** (Bun fs) — единственный на старте. `listRoots()` **OS-aware**: Windows →
  буквы дисков (+ известные папки); POSIX → `/` (+ home / тома). UI рендерит то, что вернул
  `listRoots()`, и навигирует по **непрозрачным строкам путей** от провайдера — никаких «дисков»
  в UI-коде (req 3).
- **Loopback-гейт** (req 2, owner-выбор): **отдельный bind на `127.0.0.1`** — file-browse
  эндпоинты (`fs.*`) поднимаются на loopback-only сокете, недоступном по LAN. Для локального
  провайдера это заменяет single-root песочницу (полный read по машине, но только с localhost);
  канонизация путей сохраняется.
- **Тип-фильтр (req 1):** диалог по умолчанию показывает только поддерживаемые редактором
  расширения (`.gnaural/.wav/.flac`); каталоги видны всегда для навигации. Провайдер обходит всю
  ФС — фильтрация по типу применяется в списке.
- **Menu bar (req 9):** классическая строка меню приложения; пункт **Файл → Открыть** открывает
  новый универсальный диалог. Старый `q-tree` пресетов (req 10) остаётся рядом до конца миграции.
- **Фавориты (req 11):** список закладок на источники (папки/файлы, а в будущем — provider+path
  для не-локальных источников). Пользователь добавляет/удаляет фаворит из диалога; список
  персистится (localStorage), показывается в боковой панели рядом с корнями; клик — быстрый
  переход. `presetsRoot` предзаполняет список как фаворит по умолчанию.
- **Модель записи** `FsEntry = {name, path, isDir, isSymlink, size, mtimeMs, ext, kind}`.
  Сортировка/фильтр — на клиенте для типовых каталогов (виртуализация `q-virtual-scroll`);
  опциональные серверные `sort`-параметры провайдера — на будущее для огромных каталогов.
- **Будущие провайдеры** (не в этом объёме работ): `RemoteAgentProvider` (тот же Bun на другом
  хосте), `DbProvider`, `WebProvider` — подключаются как ещё один `id` за тем же UI.

## 4. Фазы

- **Фаза 0** — план + леджер, owner-чекпоинт.
- **Фаза 1** — серверная абстракция провайдеров + `LocalFsProvider` + loopback-гейт + протокол
  `fs.listRoots/listDir/stat` + тесты.
- **Фаза 2** — универсальный диалог на Quasar: корни/крошки/навигация (OS-agnostic), три вида
  (таблица / список / иконки), сортировка, виртуализация, быстрый regexp-фильтр, клавиатура.
- **Фаза 3** — интеграция: classic menu bar (Файл → Открыть) вызывает новый диалог; `presetsRoot`
  → стартовая закладка; старый `q-tree` остаётся до конца миграции; owner-чекпоинт.
- **Фаза 4 (future, не строим сейчас)** — доп. провайдеры (remote/БД/веб), миниатюры.

## 5. Правила исполнения

- Атомарные коммиты с префиксом id шага; `verify` (vue-tsc + quasar build + bun tests) перед `done`.
- Пауза на owner-чекпоинтах (FB0.2, FB3.3) — код только после отдельного «go».
- Кросс-платформенность и loopback-гейт покрываются тестами (Фаза 1).
