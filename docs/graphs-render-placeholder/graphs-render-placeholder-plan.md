# graphs-render-placeholder — план

Регрессия: при открытии больших планов (ForestMeditation) под кривыми дорожками ~26 с пустая
область — общие графики волны и спектра появляются только когда сервер закончит рендер. Нужно на это
время показывать дорожки-плейсхолдеры с песочными часами и сообщением, по одной на каждый график.

## Требования владельца (дословно, пронумерованы)

1. «Появилась регрессия при открытии больших планов, например ForestMeditaion, графики спектра и
   волны появляются только после того, как отрендерятся на сервере. До этого момента нужно
   отображаться дорожки, в которых крутятся часы и сообщение.»
2. «Эта регрессия появился достаточно давно, заметил её вчера, но не факт, что она появилась ещё
   раньше. Думаю, что нужно сразу инструментально найти место сбоя, а не пытаться найти причину в
   коммитах.»
3. «Для каждого отображаемого графика нужно сразу отобразить placeholder.»
4. (AskUserQuestion 2026-07-19) Оформление = **Plan + ledger**; число плейсхолдеров = **«Две дорожки»**.

## Диагноз (инструментальный — req 2)

Временная инструментовка `[REGR]` (TracksPanel: таймлайн `open→render→graphs`; SpectrogramView:
`MOUNTED`/`preparing`). Прогон ForestMeditation владельцем (консоль DevTools), ключевые метки:

- `@+543ms`: расписание пришло (31 голос) → `showGtracks=true`, 124 кривые дорожки.
- `@+543ms … @+26353ms`: **~26 с `hasSpectrogramData=false`** — пустая область общих графиков.
- `@+26353ms`: `hasSpectrogramData=true`; первый `<spectrogram-view>` смонтирован `@+26491ms` — уже
  после завершения рендера.

**Место сбоя.** Общие стеки волны (TracksPanel `v-if="showWaveform && hasSpectrogramData …"`) и спектра
(`v-if="showSpectrogram && hasSpectrogramData …"`) гейтятся на `hasSpectrogramData` (= `backendAnalysis
!== null`), который встаёт только по завершении `metaSpec.open()` (серверный рендер WAV + анализ
SpectrumCore). Единственный плейсхолдер с часами — оверлей `isPreparing` внутри `SpectrogramView` —
недостижим, пока компонент не смонтирован. Панельный `openStages`-спиннер тоже подавлен, т.к. он в
`v-else`-ветке `showGtracks || hasSpectrogramData`, а `showGtracks` уже `true`. Итог: во время рендера
для общих графиков нет ни одного индикатора. Это подтверждает премису req 1 (инструментально, не по
коммитам — req 2).

## Решения

- **GP-D1.** Диагностика — инструментовка рантайма (не бисект коммитов, req 2). Логи `[REGR]` временные,
  удалить перед фикс-коммитом; результат зафиксирован здесь и в GP-D2.
- **GP-D2.** Первопричина — гейтинг общих стеков на `hasSpectrogramData`; компонент-носитель часов
  (`SpectrogramView`) монтируется только после рендера, а `openStages` подавлен при `showGtracks=true`.
- **GP-D3.** Сигнал `renderPending` на базе выделенного `metaRendering` (ref), выставляется на весь
  span `metaSpec.open()` и сбрасывается в `finally` — на успехе И на ошибке, поэтому не зависает.
  НЕ используем `metaSpec.preparing`: он остаётся `true` навсегда (headless `metaSpec` не вызывает
  `setView`, значит `refetch()` не гасит `opening`, и `preparing = busy && !hasFrame` вечно истинно).
- **GP-D4.** Плейсхолдер на КАЖДЫЙ отображаемый график (req 3 + «Две дорожки»): отдельная дорожка в
  слоте волны и в слоте спектра. Каждая гейтится теми же `show/hidden/overallMixActive`-условиями, что
  и реальная группа, минус `hasSpectrogramData` (его инвертирует `renderPending`) — раскладка совпадает
  с тем, что появится. Высота = высота первой дорожки соответствующей группы. Передача эстафеты без
  мигания: в один тик `open()` резолвится → `hasSpectrogramData=true` и `metaRendering=false` вместе,
  плейсхолдер гаснет ровно когда монтируется реальный стек.
- **GP-D5.** Текст — переиспользуем существующие i18n-ключи: заголовок группы (`tracksOverallWave` /
  `tracksOverallSpectrum`) + `stageRender` («Рендер WAV на сервере» — thin-client-корректно, один
  источник для обеих дорожек). Новых ключей нет. Часы — `q-spinner-hourglass` (как в SpectrogramView);
  стиль — тёмный фон дорожки (`#0f172a`).
- **GP-D6.** Область — только ОБЩИЕ стеки. Per-lane solo-графики монтируются рано вместе с `showGtracks`
  и имеют свои часы (SpectrogramView) — не трогаем. `WaveformView` собственного оверлея не имеет —
  покрывается плейсхолдером группы волны; спиннер в сам `WaveformView` не добавляем (вне области).

## Риски

- `metaSpec.preparing` вечно `true` — использовать нельзя (см. GP-D3); используем `metaRendering`.
- Зависание плейсхолдера при ошибке рендера — исключено `finally`-сбросом `metaRendering` и условием
  `spectrogramError === null` в `renderPending`.
- CRLF: `TracksPanel.vue` / `SpectrogramView.vue` — LF; правки Edit-инструментом сохраняют LF.
