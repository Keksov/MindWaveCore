Происхождение: пункт бэклога **BK7** ([gtrack-editor](../gtrack-editor/gtrack-editor-plan.md), owner
2026-07-12) + «отдельный будущий план версионности», обещанный в
[undo-command-log](../undo-command-log/undo-command-log-plan.md) (UC-D3) и

   к выбранному моменту. После отката можно очистить историю от восстановленной точки до текущего
   момента. Одиночный клик по списку НЕ должен приводить к потере действий.»
9. «**Гибкая архитектура (заложить на будущее, не реализовывать сейчас)**: спроектировать подсистему

## 2. Диагноз (код-анализ 2026-07-20; ПОДТВЕРЖДЁН наблюдением владельца — UG1.1, 2026-07-20)

**Подтверждение (лог `[undo-diag]` из репро владельца, ForestMeditation):** триггер — WS-событие
`schedule-changed` → `handleScheduleChanged` → `loadGnauralSchedule(path, force=true)`
([audio.ts:880-882](../../../GnauralCore/ui/stores/audio.ts)) → `schedule object replaced (load fetch)`
→ `buildModel: model rebuilt (prev: canUndo=true canRedo=false dirty=true)` → `adopt refused:
signature mismatch`: в журнале сырые драг-значения (`"timeSec":772.5752508361204,
"baseFreq":233.14042546357308`), в модели-из-файла — округлённые (`772.575, 233.14`), т.е. при
dirty-модели адопция не может сработать в принципе. Стартовое `stored undo journal adopted: 0 steps`
показывает, что диск-журнал уже был затёрт прежними rebuild'ами. Формулировка BK7 «стек живёт в
рамках формы» опровергнута: закрытие формы ни при чём, историю убивает reload по `schedule-changed`
(прилетает при load/play и записи файла).

- История undo живёт **только в in-memory `GTrackModel`** (лог voice-дельт + курсор, формат v2 из
  undo-command-log): [gtrack-model.ts:244](../../../GnauralCore/ui/composables/gtrack-model.ts).
- Модель — **процессный синглтон** (`useSharedGtrackLanes`,
  [use-gtrack-lanes.ts:1482](../../../GnauralCore/ui/composables/use-gtrack-lanes.ts)) и
  **полностью пересоздаётся** watch'ем на ЗАМЕНУ ОБЪЕКТА `audio.gnauralSchedule` — без сравнения
  контента ([use-gtrack-lanes.ts:591](../../../GnauralCore/ui/composables/use-gtrack-lanes.ts):
  `watch(schedule, (data) => buildModel(data))`) → история стирается.
- Триггеры замены объекта: **Ctrl+S** (`loadGnauralSchedule(fp, true)`,
  [TracksPanel.vue:2969](../../../GnauralCore/ui/components/TracksPanel.vue)); **Play** (Gnaural
  re-эмитит schedule на каждом load, `setGnauralSchedule` кладёт новый объект,
  [audio.ts:862](../../../GnauralCore/ui/stores/audio.ts)); **mute** (`applyVoiceStateLocally`,
  [audio.ts:382](../../../GnauralCore/ui/stores/audio.ts)); **async merge** voiceState после каждой
  загрузки ([audio.ts:356-360](../../../GnauralCore/ui/stores/audio.ts)).
- Восстановление после rebuild — `adoptUndoJournal` со **строгим равенством `JSON.stringify`-сигнатур**
  ([gtrack-model.ts:587-594](../../../GnauralCore/ui/composables/gtrack-model.ts)); float-раундтрип
  через `patchGnauralXml` (`toFixed(6)`) → Gnaural.exe и/или color-overlay проекта ломают равенство →
  адопция **молча** возвращает false → Ctrl-Z мёртв, кнопки Undo серые.
- Вопреки формулировке репро в BK7, стек **НЕ привязан к форме**: закрытие формы историю не трогает
  (`closeInspector` лишь снимает выделение). Founding-факт BK7 проверить наблюдением в Фазе 1
  (правило «verify the load-bearing premise»).

## 3. Решения (UG-Dn)

- **UG-D1 (владелец истории).** Историю undo вынести из `GTrackModel` во внешний журнал (пер-файл,
  живёт в синглтоне `useSharedGtrackLanes`), переживающий пересоздание модели. `GTrackModel` остаётся
  транзакционным ядром (beginEdit/commit → дельта), но шаги складываются наружу; rebuild модели журнал
  НЕ очищает. Плюс первая линия обороны: контент-гард в `watch(schedule)` — не пересоздавать модель,
  когда новый объект контент-эквивалентен базе текущей.
- **UG-D2 (шаг = коммит).** Расширить шаг метаданными `{ id, kind, label, atMs }`: тип операции +
  описание для панели (req 3), стабильный id и оформление «шаг ≈ коммит, линейная история = ветка
  main» — архитектурный задел на git-модель (req 9, только дизайн, без реализации веток/мерджей).
- **UG-D3 (формат/персист).** `undo.json` → **v3** (v2 без метаданных при загрузке отбрасывается,
  как v1 в UC-D5 — история best-effort). Транспорт прежний: компактный лог целиком, debounce,
  last-write-wins (PR-D7); инкрементальный append/полная версионность — вне плана — **начаты
  (2026-07-20): [undo-versioned-log](../undo-versioned-log/undo-versioned-log-plan.md)**.
- **UG-D4 (адопция).** Внутри сессии журнал передаётся новой модели **напрямую из памяти** (тот же
  файл — сигнатуры не нужны). Сигнатурный гейт остаётся только для cross-session адопции с диска, и
  при отказе пишет причину в консоль (не молча).
- **UG-D5 (панель операций).** Никаких bespoke-диалогов — 100% реюз канонической формы: PanelWindow
  (`@panel`), как «Список треков»/«Параметры». Список шагов (тип+описание+время), клик = только
  подсветка/выбор, откат исключительно по кнопке «Применить» (req 8); очистка целиком/до момента
  (req 7).
- **UG-D6 (настройки + кэш-менеджер).** Автоочистка (req 5) — в стандартном диалоге настроек
  (GnauralSettingsTab); размер `undo.json` (req 6) — строка в существующем менеджере кэша.

## 5. Риски

- **R1 (регресс undo/redo).** Поведенческие тесты `gtrack-model.test.ts` должны оставаться зелёными
  без изменений на каждом шаге Фазы 2; публичный API модели менять минимально.
- **R2 (порча данных откатом).** Ослабление адопции не должно позволить применить журнал к «не тому»
  состоянию: in-memory передача безопасна (тот же файл в той же сессии), дисковая остаётся под
  сигнатурным гейтом (UG-D4). Двухшаговый откат (req 8) стережёт случайный клик.
- **R3 (EOL).** Файлы в GnauralCore смешанные (use-gtrack-lanes.ts CRLF, gtrack-model.ts LF) —
  проверять побайтово перед правкой; никаких scripted split('\n')-правок.
- **R4 (синглтон/effectScope).** `useSharedGtrackLanes` живёт в detached effectScope всё время жизни
  приложения — новые watch'и/state вешать там же, не в компонентах.
- **R5 (сервер).** Если тронем project-store (v3-валидация) — правка сервера требует полного рестарта
  AppCore (bun --watch не подхватывает cross-repo); консоли нет — логировать в `var/*.log`.
- **R6 (staging).** Свои файлы per-repo; не трогать `server/var/*`, `server/app.cfg`,
  `server/vendor/*`. Валидатор леджера перед каждым docs-коммитом.
